# Aurora v0.1.11

本次更新可以按需关掉用不上的来源，更新检查也不再受 GitHub 接口限流影响；同时把检查耗时压到了原来的三分之一左右。内置 UnityModManager 内核升级到 0.33.3。

## 可以关掉不需要的来源

设置里新增「来源 → 启用的来源」，可以按需勾掉用不上的来源：

- 支持单独开关 ADOFAI Tools、modrift、TUF、modlist，以及「自定义站点」（配置了才出现）；
- 关掉的来源不会出现在「在线 Mod」的来源列表里；
- 检查更新（包括启动时的自动检查）会跳过它；
- 关掉默认站点时，连带跳过它的 mod 列表和 Aurora 自身的站点更新通道；
- 至少保留一个来源：关到只剩一个时，最后一个会自动勾回来并给出提示。

> 如果某些来源在你的网络下很慢（例如 TUF），关掉它可以明显缩短启动时的检查时间。

## GitHub 也可以单独关闭

GitHub 不是内容来源（不会出现在「在线 Mod」的来源列表里），但它占更新检查的相当一部分时间。

现在「更新检查」里的「同时查询 GitHub」移到了「来源 → 启用的来源」，叫「GitHub（仅检查更新）」—— 这样一来，「把用不上的都关掉」就只在一个地方完成。

## 不再出现一片「检查失败」

此前更新检查会逐个向 GitHub 的开放接口查询最新版本。这个接口在未登录状态下每小时只有 60 次额度，而且按 IP 计算：装十几个 Mod 时，检查两三次就会把额度用光，之后所有 GitHub 来源的 Mod 都会显示「检查失败」。

现在改为读取 GitHub 发布页的跳转地址来获取最新版本号，**不再消耗接口额度**：

- 一次完整检查（12 个 Mod）消耗 **0 次**接口额度，全部检查成功；
- 只有确实发现新版本、需要获取下载地址时，才会请求一次接口；
- 如果这一次正好被限流，也会保留「发现新版本」的结果，并提示前往发布页手动下载，而不是报检查失败；
- 发布页访问不了时，自动回退到原来的接口方式。

## 更新检查更快

对检查流程做了三处调整：

- 各 Mod 并发检查（最多 6 个同时进行），不再一个接一个地等；
- TUF、modlist、modrift 的目录并发拉取，只等最慢的那个；
- 来源对象改为复用，避免反复创建网络客户端和重复握手。

实测（冷缓存、全开来源、12 个已装 Mod）：

| 版本 | 检查耗时 |
| --- | --- |
| v0.1.10 | 16.2 秒 |
| v0.1.11 | **6.1 秒** |

其中第三方源目录的耗时从 7.6 秒降到 3.8 秒。实际耗时和网络环境、已安装的 Mod 数量有关。

## 切页不再「顿一下」

「已安装」页在显示时会同步重建 Mod 列表（约 100 毫秒），正好卡在页面切换动画开始的时候。现在改为等切换动画播完再重建，切到该页不会再停顿；更新检查结束后的列表刷新也做了同样处理。

## 内置 UnityModManager 更新

内置内核从 0.33.2 升级到 **0.33.3**。在「安装 / 修复加载器」里选择内置内核时用的就是这个版本；如果游戏里部署的还是旧版本，「UMM 环境」页面会提示更新。

## 诊断日志

调试日志现在会记录每个 Mod 的检查结果和耗时，以及每个来源取到多少条数据：

```text
[check] AccurateJudgementBar 用时 1667ms · 已是最新
[check] 源 tuf 取到 160 条（1967ms）
```

反馈问题时附上日志，可以直接看出是哪个环节慢或者失败。

## 升级方式

使用 v0.1.6 或更高版本的用户，可以在软件内点击“立即更新”。也可以退出软件后手动升级：

| 版本 | 操作 |
| --- | --- |
| 安装版 | 运行 `Aurora-Setup-0.1.11.exe`，覆盖安装 |
| 绿色版 | 将 ZIP 解压并覆盖到原来的程序目录 |

> v0.1.5 及更早版本自带的自动更新存在问题，请手动下载安装包覆盖安装，或解压 ZIP 覆盖原程序目录。

原有设置、收藏和日志会保留。升级前建议备份游戏目录中的 `Mods` 文件夹。
