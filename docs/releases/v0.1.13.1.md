# Aurora v0.1.13.1

本次是一个小补丁，修复本地 ZIP 安装大型 Mod 时磁盘读写过高、窗口短暂无响应的问题。

## 本地 ZIP 安装不再复制旧 Mod 的全部文件

部分 Mod 会在自己的目录里保存大量生成数据（例如 ChartRendering 的 `Workspace` 渲染缓存，单个目录可能超过 10 GB）。此前覆盖安装会把旧目录整体复制到暂存目录，导致几十 GB 的额外读写，安装期间窗口也会无响应。

现在：

- 旧目录独有的文件优先使用**硬链接**合并到暂存目录，不再复制实体数据；
- 新包中的文件仍然覆盖旧文件；
- 文件系统不支持硬链接或跨卷时，自动回退为普通复制；
- 本地 ZIP 安装改为后台执行，界面会显示「正在安装」，不会再卡死。

> 硬链接只避免额外复制一份，Mod 自己生成的 `Workspace` 等数据仍然占用原有磁盘空间；Aurora 不会自动删除这些数据。

## 其他

- 安装期间关闭窗口仍会触发「关键操作进行中」确认；
- 新增回归测试：旧目录中的大文件更新后仍然保留，且文件身份不变（确认使用的是硬链接，而不是复制）。

## 升级方式

**建议所有用户更新。**

使用 v0.1.6 或更高版本的用户，可以直接在软件内点击「立即更新」。

也可以退出软件后手动升级：

| 版本 | 操作 |
| --- | --- |
| 安装版 | 运行 `Aurora-Setup-0.1.13.1.exe`，覆盖安装 |
| 绿色版 | 将 ZIP 压缩包解压并覆盖到原来的程序目录 |

> v0.1.5 及更早版本自带的自动更新功能存在问题，请手动下载安装包覆盖安装，或解压 ZIP 覆盖原程序目录。

升级不会影响原有设置、收藏和日志。建议升级前备份游戏目录中的 `Mods` 文件夹。
